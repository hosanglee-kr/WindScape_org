- 선풍기의 작동은
지정된 고정속도/프리셋으로 고정되서 계속 작동 될지 아니면 스케줄에 설정에따라 고정속도/프리셋으로 변동되서 작동될지  결정됨
(스케줄모드와 컨티뉴스모드)

- 모션은 스케줄모드와 컨티뉴스모드 중에 선풍기가 작동 될지 말지만 결정


아주 정확하게 핵심을 짚으셨습니다.
지금 구조에서 말씀하신 개념은 **“시뮬레이션 제어권의 흐름과 동작 모드 전환”**의 근간입니다.
정리하면, 백엔드의 S10_Scheduler(시간 제어)와 M10_MotionLogic(센서 제어)는
**“무엇을 조정하느냐”**가 다르고,
**“결정권의 우선순위”**도 명확히 다릅니다.

아래는 이를 명세 수준으로 재구성한 설계 정리 초안입니다 👇


---

🧩 1️⃣ 기본 구조 (WindScape 동작 모드 개념)

구분	설명	제어 주체

🌀 Continuous Mode (연속 모드)	사용자가 지정한 고정 프리셋/풍속으로 계속 작동.	사용자가 수동 지정 (config.sim)
⏰ Schedule Mode (스케줄 모드)	S10_Scheduler가 설정한 시간대별 프리셋/강도로 변동 작동.	S10_Scheduler
🕹️ Motion Logic (모션 로직)	PIR 등 감지 여부에 따라 “작동/정지 여부”만 결정.	M10_MotionLogic

⚙️ 2️⃣ 동작 우선순위 체계

[모션 로직] → [시뮬레이션 모드(스케줄 or 연속)] → [시뮬레이션 엔진]

순위	역할	설명

①	모션(M10)	선풍기를 켤지/끌지 결정 (active / inactive)
②	시뮬레이션 모드(S10)	“켜져 있을 때 어떤 바람으로 동작할지” 결정
③	물리엔진(S10_Simulation)	최종 PWM, 풍속, 난류 계산 수행



---

🕹️ 3️⃣ 동작 시나리오별 예시

상황	결과	설명

🟢 Continuous + Motion 활성화	PIR 감지 시 → 지정 preset 작동 / 미감지 시 → 정지	모션이 ON/OFF만 제어
🔵 Schedule + Motion 활성화	PIR 감지 시 → 현재 시간대 스케줄 preset으로 작동 / 미감지 시 → 정지	스케줄과 모션 병행
🟣 Continuous + Motion 비활성화	항상 지정 preset 으로 작동	기본 연속 모드
🟠 Schedule + Motion 비활성화	시각에 따라 preset 자동 변경	자동 시간 모드

🧭 4️⃣ 실제 코드 레벨 설계 예시

enum T_S10_RunMode {
    S10_MODE_CONTINUOUS = 0,
    S10_MODE_SCHEDULED  = 1
};

class CL_WS10_WindScapeSimulator {
public:
    void tick() {
        // 1. 모션 상태 확인
        bool motionActive = CL_M10_MotionLogic::isActive();

        // 2. 작동 여부 결정
        if (!motionActive && g_A10_config_root.motion.motionEnabled) {
            _sim.S10_stopFan();      // PWM = 0, wind = 0
            return;
        }

        // 3. 모드에 따른 preset 적용
        if (g_A10_config_root.mode == S10_MODE_SCHEDULED)
            CL_S10_Scheduler::tick();     // 시간대별 preset 적용
        else
            _sim.S10_applyPreset(g_A10_config_root.sim.preset,
                                 g_A10_config_root.sim.intensity,
                                 g_A10_config_root.sim.variability);

        // 4. 물리엔진 tick
        _sim.S10_tick();
    }
};

> 🔹 S10_stopFan()은 실제 PWM Duty를 0으로 낮추며, 풍속 목표치도 0으로 설정
🔹 S10_applyPreset()은 preset과 intensity를 즉시 반영
🔹 tick() 루프는 항상 “Motion → Mode → Simulation” 순서로 호출

✅ 결론

지금 말씀하신 정의대로라면:

> 모션(M10) = “선풍기를 켤지 말지만 결정”
모드(S10) = “켜졌을 때 어떤 방식으로 돌지(스케줄 vs 연속)” 결정



이 방식이 가장 명확하고, 실기기(ESP32 + 선풍기 PWM)에서도 제어 루프를 안정적으로 유지합니다.
또한 향후 UI에서 모션 ON/OFF 토글과 모드 전환 버튼을 손쉽게 추가할 수 있습니다.
